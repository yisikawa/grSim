# SSL対戦クライアント — 戦術的パスワーク 設計書

日付: 2026-07-15
ステータス: 計画フェーズへ承認済み
前提: `docs/superpowers/specs/2026-07-14-ssl-match-clients-design.md`(実装済み・develop にマージ済み)の拡張

## 目的

現行の `clients/python/` 戦略(ボール最近接ロボットがボールを追ってゴール方向へ蹴るだけ)を、**ポゼッション重視のパスワーク**ができる構成へ拡張する。目指す見た目: ロボットが空いている味方を選んでパスし、受け手がパスラインに入ってトラップし、ボールを持たない味方はパスコースが開ける位置へ動き直す。シュートは明確なチャンス(シュートコースが大きく開いていてゴールに近い)のみ。

対象は戦略層のみ。通信層(`vision.py` / `referee.py` / `commands.py`)、エントリポイント、HALT/STOP での全停止挙動は変更しない。両チームは同じ `TeamStrategy` を共有するため、この変更で青・黄両方がパス回しをする。

### スコープ

- 含む: パスコース評価(敵による遮断リスク)、受け手の連携(蹴る側と受ける側の役割同期)、オフボールの動き直し(固定フォーメーションからの脱却)
- 含まない: ワンツー等の連続プレー、本格的な経路計画、審判細則(フリーキック配置等)への対応

## モジュール構成

```
ssl_client/
  world.py       # 既存 + ボール速度推定を追加
  evaluation.py  # 新規: パス/シュートコース評価の純粋関数
  roles.py       # 新規: ロールごとの目標計算 + 運動プリミティブ
  strategy.py    # 改修: ロール割当てとチーム状態機械のみのコーディネーターに縮小
```

- `_seek` / `_face` / `_normalize_angle` / `_apply_separation` などの運動プリミティブは `strategy.py` から `roles.py` へ移動する(公開名にリネームしてよい)。
- `strategy.py` の外部インターフェース `TeamStrategy(TeamConfig).compute_commands(world, referee_running) -> list[RobotCommand]` は変更しない(エントリポイントと既存テストへの互換のため)。

## WorldModel 拡張(ボール速度推定)

`BallObservation` に `vx: float`, `vy: float`(m/s、フィールド座標系)を追加する。

- 推定: 連続する Vision フレームの位置差分 ÷ `t_capture` 差分。`dt <= 0` や `dt` が異常に大きい(> 0.5 s、フレーム落ち)場合は前回速度を据え置く。
- 平滑化: 指数移動平均 `v = α * v_raw + (1 - α) * v_prev`、α = 0.5。
- 実装は純粋関数 `estimate_ball_velocity(prev: BallObservation, curr_x, curr_y, curr_t) -> (vx, vy)` とし、`update_from_detection_frame` から呼ぶ。初回観測は速度 (0, 0)。

## チーム状態機械(strategy.py)

チーム全体でひとつの状態を持つ。状態は `TeamStrategy` インスタンス変数(このプロセスが扱う1チーム分)。

```
CHASE ──(自チームの誰かが保持)──> POSSESS ──(パスキック実行)──> PASS_IN_FLIGHT
  ^                                  │                             │
  │                                  └──(保持を失った)─────────────┤
  └──(ボール減速/タイムアウト/受け手保持で再判定)───────────────────┘
```

- **CHASE**: キーパー以外で最もボールに近い1台(チェイサー)がボールへ向かう(現行アタッカーと同じ動き)。他はサポート(後述)。
  - → POSSESS: チェイサーの保持判定が真になったとき。
- **POSSESS**: ホルダー(保持したロボット)はドリブラーON。毎 tick 評価(後述)でパス/シュート/ドリブル前進を選ぶ。パスに決めたら受け手方向へ旋回し、角度誤差 < 0.35 rad でキック。蹴った瞬間に受け手IDを記録して → PASS_IN_FLIGHT。
  - → CHASE: ホルダーが保持を失った(ボールとの距離 > 0.5 m)とき。
- **PASS_IN_FLIGHT**: 記録された受け手のみボールへ向かう(後述のインターセプト)。他はサポート。ホルダーだった機体もサポートに戻る。
  - → CHASE: ボール速度 < 0.5 m/s になった、受け手の保持判定が真になった、または状態開始から 2.0 s 経過(タイムアウト)のいずれか。遷移先は常に CHASE とし、受け手がそのまま保持していれば次 tick の通常の CHASE→POSSESS 遷移で POSSESS に入る(特別扱いしない)。

**保持判定**(共通述語): ロボットとボールの距離 < 0.12 m かつボール速度 < 0.5 m/s。

HALT/STOP(`referee_running == False`)は現行どおり状態機械より先に処理し、全ロボットに速度ゼロを送る。このとき状態は CHASE にリセットする。

## パス/シュートコース評価(evaluation.py)

すべて純粋関数。係数はモジュール定数としてチューニング可能にする。

### コース安全度(共通プリミティブ)

```
lane_safety(p_from, p_to, opponents) -> float  # 0..1
  = min(各敵ロボットから線分 p_from→p_to への最短距離, CAP) / CAP
  CAP = 0.5 m。敵がいなければ 1.0。
```

### パス候補スコア

ホルダーから各味方(キーパー除く)R への:

```
pass_score(holder, R, opponents, opponent_goal) =
    lane_safety(holder, R, opponents)
  − W_DIST · dist_penalty(‖R − holder‖)      # [0.8 m, 4.0 m] を外れた分に比例
  + W_FWD  · forward_progress(holder, R, opponent_goal)  # R が敵ゴールに近づく度合い、0..1 に正規化
W_DIST = 0.3, W_FWD = 0.3
```

### シュートスコアと選択ロジック(パス優先)

```
shoot_score = lane_safety(ball, opponent_goal_center, opponents)

if shoot_score > 0.8 かつ ゴールまでの距離 < 2.5 m:
    シュート(kick_speed = 4.0 m/s、ゴール中心を向いて)
elif 最良の pass_score > 0.3:
    その味方へパス(kick_speed = clamp(パス距離 × 1.5, 1.5, 3.5) m/s)
else:
    敵ゴール方向へドリブル前進(速度控えめ 1.0 m/s、ドリブラーON)
```

## ロール(roles.py)

- **キーパー**: 現行のまま(ゴールライン上でボールのYを追従)。
- **チェイサー**(CHASE時): ボールへ `seek`、ボールの方を向く、ドリブラーON。
- **ホルダー**(POSSESS時): 上記評価に基づく蹴り分け。
- **レシーバー**(PASS_IN_FLIGHT時): インターセプト点 = ボール位置から速度方向へ伸ばしたレイ上の、自機に最も近い点。そこへ `seek` し、ボールの方を向き、ドリブラーON。ボール速度がほぼゼロならボール位置そのものへ。
- **サポート**(それ以外の非キーパー全員): 動き直し。現行の固定スロットを基準位置とし、その周辺の候補点(基準点 + 横方向 {−0.8, 0, +0.8} m × 前後 {0, +0.5} m の6点)から、`lane_safety(ボール位置, 候補点, 敵)` が最大の点を選んで `seek`。同点なら基準スロットに近い方。既存の反発分離(`_apply_separation`)は全ロール共通で維持。

ロール割当ての優先順: キーパー(現行どおり最小ID固定)→ チェイサー/ホルダー/レシーバー(状態機械が決定)→ 残り全員サポート。

## エラー処理・フォールバック

- Vision 喪失(ボール/ロボット未観測): 現行どおり空コマンドを返す。
- 記録した受け手IDが視界から消えた: PASS_IN_FLIGHT を即終了して CHASE へ。
- 状態機械のタイムアウト(PASS_IN_FLIGHT 2.0 s)は必須実装 — どんな評価バグでも試合が固まらない安全弁。
- 敵チームのロボットが0台でも動くこと(lane_safety = 1.0 になり常時パス/シュート可)。

## テスト方針

既存28テストは全て維持する(`compute_commands` の外部仕様は不変。ただし内部リファクタリングでテストのimport先修正が必要な場合は、テストの検証内容を変えずに追随してよい)。

新規テストは全て純粋関数・合成データ対象(grSim不要):

- `world`: 速度推定(等速直線で正しい値、dt=0 で据え置き、EMA平滑化)
- `evaluation`: lane_safety(敵が線分上/脇/遠方)、pass_score の距離・前進ボーナス、パスvsシュートの閾値選択
- `roles`: レシーバーのインターセプト点、サポートの候補点選択(遮る敵を置くと別候補に移る)
- `strategy`: 状態遷移(保持→POSSESS、キック→PASS_IN_FLIGHT、減速/タイムアウト→CHASE)、HALT で状態リセット

目安 +25〜35 テスト。

## 検証方法(手動)

grSim + ssl-game-controller + 両クライアントを起動し Force Start:

1. ボールを持ったロボットが即席で蹴らず、味方の方を向いてからパスする
2. パス中、受け手がボール軌道に入って迎えに行く
3. ボールを持たない味方が固定位置ではなく、位置を小刻みに調整する
4. ゴール近くでシュートコースが開いたときだけシュートする
5. Stop/Halt で全停止(現行どおり)
